Introduction

Welcome to this lesson on object-oriented programming (OOP) in Python. Since you're already familiar with procedural programming in Python, this lesson will focus on the key concepts of classes, objects, inheritance, encapsulation, and polymorphism.

Object-oriented programming is a paradigm that organizes code into objects, which are instances of classes. This approach can make code more modular, reusable, and easier to maintain.

Classes and Objects

A class is a blueprint for creating objects. It defines attributes (data) and methods (functions) that the objects will have. A single class can be used to create many objects. Here's a simple example:

class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    def bark(self):
        print(f"{self.name} says: Woof!")
# End class definition and begin test code here.

# Creating an object (instance) of the Dog class
my_dog = Dog("Buddy", 3)
# The above statement looks like an ordinary function
#  call except that Dog is the name of a class and is
#  not the name of a function.

# Accessing attributes
print(my_dog.name)  # Output: Buddy

# Calling methods
my_dog.bark()  # Output: Buddy says: Woof!
#===================================================================

Key points

  • The __init__ method is a special method (constructor) that initializes the object's attributes.
  • self refers to the instance of the class and is used to access its attributes and methods.

The Use of Self

The use of self in Python classes is a common point of confusion for those new to object-oriented programming in Python.

The self parameter is used to represent the instance of the class. It's a convention in Python to name this first parameter self, but you could technically use any valid variable name. However, sticking to self is highly recommended for readability and consistency.

Let's break down the use of self

Why Use Self?

The use of self allows each instance of the class (object) to have its own set of attributes. Without it, you couldn't have multiple instances of a class with different attribute values. Here's an example.

class Car:
    def __init__(self, make, model): #constructor
        self.make = make
        self.model = model
    
    def describe(self): #instance method
        return f"This car is a {self.make} {self.model}"
# End class definition and begin test code here.

# Create two objects with different attributes from the same class
car1 = Car("Toyota", "Corolla")
car2 = Car("Honda", "Civic")

print(car1.describe())  # Output: This car is a Toyota Corolla
print(car2.describe())  # Output: This car is a Honda Civic

Method Definition

When you define an instance method within a class, you always include self as the first parameter. (See a discussion of class methods and static methods later.)

class MyClass:
    def my_method(self, arg1, arg2):
        # method body

Why Include Self as the First Parameter?

Here's why we typically use self as the first parameter in instance method definitions, and when we might choose not to.

The reason is rooted in how Python implements object-oriented programming

Instance Methods

For instance methods, self (or some other name) is always the first parameter. This is because when you call a method on an instance (object), Python automatically passes a reference to the instance as the first argument. That reference can be used later to access attributes or methods belonging to that specific object.

Here's some example code.

class MyClass:
    def instance_method(self, arg1, arg2):
        pass
# End class definition and begin test code here.

obj = MyClass() #create an object of the class
#call an instance method on the object
obj.instance_method(1, 2) 
# Python translates this to
# MyClass.instance_method(obj, 1, 2)

(In case you are unfamiliar, the pass statement in Python is a null operation — when it is executed, nothing happens. It's a placeholder that is syntactically needed to create an empty code block.)

Why Do We Call Them "Instance Methods"?

Instance, (or instance of a class), is another term for object.

The term "instance method" is used to distinguish it from other types of methods in object-oriented programming. Let's break this down :

  1. "Instance" part
    1. An instance method is bound to an instance (object) of a class. (From an operational perspective, the code behaves as if each object has one.)
    2. It operates on a specific instance (object) of the class.
    3. It can access and modify the instance's attributes.
    4. It can call other instance methods belonging to the same object and typically uses self to do so.
  2. Why "instance"
    1. These methods are called on instances (objects) of a class, not on the class itself.
    2. Each call to an instance method is associated with a particular object.
  3. Contrast with other method types
    1. Class methods: Operate on the class itself, not on instances.
    2. Static methods: Don't operate on instances or the class.
  4. Automatic self parameter
    1. Instance methods automatically receive a reference to the instance as the first parameter (conventionally named self).
    2. This allows the method to access and modify the specific instance's data.
Usage Example
class Dog:
    def __init__(self, name):
        self.name = name
    
    def bark(self):  # This is an instance method
        print(f"{self.name} says: Woof!")#Access the name attribute
# End class definition and begin test code here.

fido = Dog("Fido")
fido.bark()  # Calling the instance method on a specific instance

Here, bark() is an instance method because

  • It's called on a specific instance (fido).
  • It can access the instance's attributes (like self.name).
  • Python automatically passes the instance (fido) as the self parameter.
Behavior
  • Instance methods can access and modify instance-specific data.
  • They can also access class-level data, but typically work with instance-specific information.
Synopsis

We call it an "instance method" because it's intrinsically tied to and operates on instances of the class. This terminology helps differentiate the method's behavior and scope within the object-oriented paradigm.

Class Methods

Class methods use cls as the first parameter by convention, not self. They're defined using the @classmethod decorator. Here is an example.

class MyClass:
    @classmethod
    def class_method(cls, arg1):
        pass

Why Do We Call Them "Class Methods"?

The term "class method" is used to describe a specific type of method in object-oriented programming. Let's break down why we call them "class methods"

  1. "Class" part
    1. These methods are bound to the class itself, not to instances of the class.
    2. They operate on class-level data rather than instance-specific data.
  2. Why "class"
    1. These methods can be called on the class directly, without creating an instance (object) of the class.
    2. They have access to the class itself as their first parameter (conventionally named cls).
  3. Contrast with instance methods
    1. Instance methods operate on specific instances and their data.
    2. Class methods operate on class-level data and behaviors.
  4. The @classmethod decorator
    1. In Python, class methods are defined using the @classmethod decorator.
    2. This decorator tells Python to treat the method differently from instance methods.
  5. Automatic cls parameter
    1. Class methods receive the name of the class as the implicit first parameter, conventionally named cls.
    2. This allows the method to access or modify class-level attributes and call other class methods.
Usage Example
class Student:    
    school_name = "Python High"
    
    def __init__(self, name):#Constructor
        self.name = name
    
    @classmethod
    def change_school(cls, new_school):
        cls.school_name = new_school
    
    @classmethod
    def get_school_name(cls):
        return cls.school_name
# End class definition and begin test code here.

# Using class methods without creating an instance
print(Student.get_school_name())  # Output: Python High
Student.change_school("Code Academy")
print(Student.get_school_name())  # Output: Code Academy

Here, change_school() and get_school_name() are class methods because

  • They're decorated with @classmethod.
  • They operate on the class (Student) itself, not on instances.
  • They can be called on the class without creating an instance.
Common use cases
  • Alternative constructors
  • Methods that modify class-level state
  • Factory methods

(The first and last use cases are beyond the scope of this course.)

Synopsis

We call them "class methods" because they are methods that are closely associated with and operate on the class itself, rather than on specific instances of the class. This terminology helps distinguish their behavior and scope within the object-oriented paradigm, highlighting their ability to work with class-level data and their accessibility without needing to instantiate an object the class.

Static Methods

Static methods don't automatically receive any implicit first argument. They're defined using the @staticmethod decorator. Here is an example.

class MyClass:
    @staticmethod
    def static_method(arg1):
        pass

Why Do We Call Them "static methods"?

The term "static method" comes from object-oriented programming concepts and has specific meaning in Python. Let's break down why we call them "static methods"

  1. "Static" part
    1. "Static" implies that these methods don't depend on the state of the object or the class.
    2. They are "statically" bound to a class, meaning they don't change based on the instance or class they're called from.
  2. Independence
    1. Static methods don't have access to self (the instance) or cls (the class).
    2. They behave like regular functions but are defined inside a class for namespace organization.
  3. No automatic first argument
    1. Unlike instance methods (self) or class methods (cls), static methods don't receive any implicit first argument.
  4. The @staticmethod decorator
    1. In Python, static methods are defined using the @staticmethod decorator.
    2. This decorator tells Python that the method doesn't need to receive the class or instance as its first argument.
Usage Example 
class MathOperations:
    @staticmethod
    def add(x, y):
        return x + y
    
    @staticmethod
    def is_even(num):
        return num % 2 == 0
# End class definition and begin test code here.

# Using static methods
print(MathOperations.add(5, 3))  # Output: 8
print(MathOperations.is_even(6))  # Output: True

Here, add() and is_even() are static methods because

  • They're decorated with @staticmethod.
  • They don't depend on instance or class state.
  • They can be called on the class without creating an instance.
Why "static"
  • The term comes from other programming languages where "static" members belong to a class rather than instances.
  • In Python, "static" emphasizes that these methods are stateless with respect to the class and its instances.
Use cases
  • Utility functions related to the class but not dependent on its state.
  • Helper functions that don't need access to class or instance attributes.
Synopsis

We call them "static methods" because they are statically bound to the class and don't depend on or modify the state of the class or its instances. This terminology helps distinguish them from instance and class methods, highlighting their independence from the object-oriented nature of the class they're defined in. Static methods essentially act like regular functions but are placed in classes for logical grouping and namespace management.

Classes and Objects Summary

When you define an instance method within a class, you always include self as the first parameter. Class methods use cls as their first parameter, and static methods don't require a special first parameter.

The reason for using self in instance methods is to give the method access to the instance's attributes and other methods. Without self, the method wouldn't be able to reference or modify the instance's state.

This explicit self parameter is a design choice in Python. In some other languages (like Java or C++), the reference to the current instance is implicit and doesn't appear in the method signature. Python's approach makes the instance reference explicit, which can make the code more readable and the behavior more clear, especially for newcomers to the language.

Accessing Instance Attributes

self is used to access and modify the attributes of the instance. Here is an example.

class Person:
    def __init__(self, name):
        self.name = name  # Creating an instance attribute
    
    def greet(self):
        # Accessing the instance attribute
        print(f"Hello, my name is {self.name}")

Method Calls Within the Class

When calling one method from another within the same class, you use self.

class Calculator:
    def add(self, a, b):
        return a + b
    
    def add_and_double(self, a, b):
        # Calling another method using self
        return self.add(a, b) * 2

Automatic Self when Calling Methods

When you call a method on an instance, Python automatically passes a reference to the instance as the first argument. You don't need to pass self explicitly.

person = Person("Alice")#Create an object of the class Person
# Python automatically passes 'person' as 'self'
person.greet()

This is equivalent to

Person.greet(person)  # Explicitly passing the instance

Class Methods vs. Instance Methods

Regular methods (instance methods) automatically receive self. If you want a method that doesn't need access to instance attributes, you can use a class method or static method

class MyClass:
    @classmethod
    def class_method(cls):
        # 'cls' is conventionally used instead of 'self' for class methods
        print("This is a class method")
    
    @staticmethod
    def static_method():
        # No 'self' parameter for static methods
        print("This is a static method")

Inheritance

Inheritance allows you to create a new class based on an existing class, inheriting its attributes and methods. Inheriting from a class is sometimes called extending a class.

Example Code

Here's an example.

class Animal:
    def __init__(self, species):
        self.species = species
    
    def make_sound(self):
        pass
# End superclass definition

class Cat(Animal): #Cat extends Animal
    def __init__(self, name):
        super().__init__("Cat")
        self.name = name
    
    def make_sound(self): #Override make_sound method
        return f"{self.name} says: Meow!"
# End subclass definition and begin test code here.

my_cat = Cat("Whiskers")
print(my_cat.species)  # Output: Cat
print(my_cat.make_sound())  # Output: Whiskers says: Meow!

Let's break this example down and examine the various code fragments.

Class Definitions

class Animal:
    def __init__(self, species):
        self.species = species
    
    def make_sound(self):
        pass

This code fragment performs the following actions:

  • Defines a class named Animal.
  • Defines the constructor (__init__) method that takes self and species as parameters.
  • Sets the species attribute of the instance to the provided species value.
  • Defines a method make_sound() that does nothing (placeholder method). This is sometimes called an abstract method because it has no defined behavior.
class Cat(Animal):
    def __init__(self, name):
        super().__init__("Cat")
        self.name = name
    
    def make_sound(self):
        return f"{self.name} says: Meow!"

This code fragment performs the following actions:

  • Defines a class Cat that inherits from (extends) Animal. Note that the name of the class being extended is passed as an argument in the constructor for the class named Cat.
  • Defines the constructor for Cat that takes self and name as parameters.
  • Calls the superclass (Animal) constructor with "Cat" as the species.
  • Sets the name attribute of the instance to the provided name value.
  • Overrides the make_sound() method to return a string with the cat's name and sound.

That ends the class definitions.

Test Code

The beginning of the test code is shown in the following fragment.

my_cat = Cat("Whiskers")

This code creates an instance (object) of the Cat class with the name "Whiskers" and assign's the object's reference to the variable named my_cat.

print(my_cat.species)  # Output: Cat

This fragment prints the species attribute of the object referred to by my_cat. This was set in the Animal constructor by code in the Cat constructor.

print(my_cat.make_sound())  # Output: Whiskers says: Meow!

This fragment calls the make_sound method on the object referred to by my_cat and prints the result.

This code demonstrates

  1. Inheritance (Cat inherits from or extends Animal),
  2. Method overriding (Cat overrides make_sound()).
  3. The use of super() to call the superclass constructor.

It also shows how attributes set in the superclass (species) are accessible in the subclass instance.

A More Interesting Example

Here is a slightly more interesting example where the Animal class defines a concrete definition of the make_sound method. The Cat class extends the Animal class and overrides the make_sound method. Test code then exercises the two classes and demonstrates the effect of overriding a method.

class Animal:
    def __init__(self, species, sound):
        self.species = species
        self.sound = sound
    
    def make_sound(self):
        return f"This {self.species} makes a {self.sound} sound."

class Cat(Animal):
    def __init__(self, name):
        super().__init__("Cat", "meow")
        self.name = name
    
    def make_sound(self):
        return f"{self.name} says: {self.sound.capitalize()}!"
# End definitions and begin test code here.

# Create instances and test
generic_animal = Animal("dog", "woof")
my_cat = Cat("Whiskers")

print(generic_animal.make_sound())  # Output: This dog makes a woof sound.
print(my_cat.species)               # Output: Cat
print(my_cat.make_sound())          # Output: Whiskers says: Meow!

Let's go through the details:

  1. In the Animal class:
    1. The __init__ method now takes an additional sound parameter.
    2. We store both species and sound as instance attributes.
    3. The make_sound method now returns a string using these attributes.
  2. In the Cat class:
    1. The __init__ method calls the superclass constructor with "Cat" as the species and "meow" as the sound.
    2. The make_sound method is overridden to provide a cat-specific implementation, using the name and sound attributes.
  3. In the test code:
    1. We create a generic animal (a dog) to demonstrate the Animal class's make_sound method.
    2. We create a cat instance as before.
    3. We then demonstrate calling make_sound on both the generic animal and the cat.

This version shows how a base class can provide a default implementation that subclasses can either use as-is (if appropriate) or override with more specific behavior. It also demonstrates how subclasses can leverage the attributes and methods of their superclass.

Encapsulation

Encapsulation is the bundling of data and the methods that operate on that data within a single unit (class). It also involves restricting direct access to some of an object's components.

Example Code

class BankAccount:
    def __init__(self, balance):
        self._balance = balance  # Protected attribute
    
    def deposit(self, amount):
        if amount > 0:
            self._balance += amount
    
    def withdraw(self, amount):
        if 0 < amount <= self._balance:
            self._balance -= amount
    
    def get_balance(self):
        return self._balance
# End class definition and begin test code here.

account = BankAccount(1000)
account.deposit(500)
print(account.get_balance())  # Output: 1500

Here's a detailed explanation of the above code.

Class Definitions

class BankAccount:
  • Define a class named BankAccount.
def __init__(self, balance):
        self._balance = balance  # Protected attribute
  • Define the constructor method that takes self and balance as parameters.
  • Initialize a protected attribute _balance with the given balance value. The underscore prefix is a convention indicating that this attribute should not be accessed directly from outside the class.
def deposit(self, amount):
        if amount > 0:
            self._balance += amount
  • Define a deposit method that takes self and amount as parameters.
  • If the amount is greater than 0, add it to the _balance.
def withdraw(self, amount):
        if 0 < amount <= self._balance:
            self._balance -= amount
  • Define a withdraw method that takes self and amount as parameters.
  • If the amount is greater than 0 and less than or equal to the current _balance, subtract it from _balance.
def get_balance(self):
        return self._balance
  • Define a get_balance method that returns the current value of _balance.

Test Code

Begin the test code here.

account = BankAccount(1000)
  • Create an instance (object) of BankAccount with an initial balance of 1000. Assign the object's reference to the variable named account.
account.deposit(500)

Call the deposit method on the object referred to by account to add 500 to the balance.

print(account.get_balance())  # Output: 1500

Call the get_balance method on the object referred to by account and print the result, which is 1500 (1000 initial + 500 deposited).

Synopsis

This code demonstrates encapsulation, a key principle of object-oriented programming. The _balance attribute is protected, and access to it is controlled through methods (deposit, withdraw, get_balance). This allows the class to enforce rules (like preventing negative deposits or overdrafts) and provides a clean interface for interacting with the account balance.

Note however, that In Python, while a variable with a name like _balance is considered protected, it is not truly private. By convention, a single underscore prefix (e.g., _balance) indicates that the variable is intended for internal use within the class or its subclasses. However, this is just a convention and does not enforce strict access control. The variable can still be accessed from outside the class, though it is generally discouraged.

If you want to make a variable even more private, you can use a double underscore prefix (e.g., __balance). This triggers name mangling, which makes it harder (but not impossible) to access the variable from outside the class. Even with name mangling, the variable can still be accessed using its mangled name.

If you need for the privacy of instance variables to be strictly enforced, you need to switch to a different programming language such as Java or C++.

Polymorphism

Polymorphism allows objects of different classes to be treated as objects of a common base class.

Example Code

Here is some sample code.

class Shape:
    def area(self):
        pass
# End class definition

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    
    def area(self):
        return self.width * self.height
# End class definition
class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    
    def area(self):
        return 3.14 * self.radius ** 2
# End class definition and begin test code

shapes = [Rectangle(5, 3), Circle(2)]
for shape in shapes:
    print(f"Area: {shape.area()}")
'''
Output:
Area: 15
Area: 12.56
'''

Here is a detailed explanation of the above code.

Class Definitions

Shape Class
class Shape:
    def area(self):
        pass
  • Purpose: This is a base class (or abstract class) that defines a common interface for all shapes.
  • Approach: The area method is defined but not implemented (pass is a placeholder). This method is intended to be overridden by subclasses.
Rectangle Class
class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    
    def area(self):
        return self.width * self.height
  • Inheritance: Rectangle inherits from Shape.
  • Constructor: The __init__ method initializes the width and height attributes.
  • Approach: The area method calculates the area of the rectangle using the formula width * height.
Circle Class
class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    
    def area(self):
        return 3.14 * self.radius ** 2
  • Inheritance: Circle inherits from Shape.
  • Constructor: The __init__ method initializes the radius attribute.
  • Approach: The area method calculates the area of the circle using the formula π * radius^2 (approximating π as 3.14).

Test Code

Creating Instances
shapes = [Rectangle(5, 3), Circle(2)]
  • List of Shapes: A list named shapes is created, containing instances of Rectangle and Circle.
  • Rectangle Instance: Rectangle(5, 3) creates a rectangle with a width of 5 and a height of 3.
  • Circle Instance: Circle(2) creates a circle with a radius of 2.
Calculating and Printing Areas
for shape in shapes:
    print(f"Area: {shape.area()}")
  • Loop: Iterates over each shape in the shapes list.
  • Method Call: Calls the area method on each shape instance.
  • Output: Prints the area of each shape.

Output

  • For the Rectangle with width 5 and height 3:
    • Area = 5 * 3 = 15
  • For the Circle with radius 2:
    • Area = 3.14 * 2^2 = 3.14 * 4 = 12.56

So, the output will be:

Area: 15
Area: 12.56

Synopsis

This code demonstrates the use of inheritance and polymorphism in Python. The Shape class provides a common interface, and the Rectangle and Circle classes implement the area method in their own way. The test code shows how you can work with a list of different shapes and call the area method on each one, without needing to know the specific type of shape. That is what polymorphism is all about.
